Beginner1. The big picture

JNI (Java Native Interface) lets Java call functions written in C/C++, and lets C++ call back into Java. Java never links to your C++ source. It loads a compiled shared library (.so on Linux) at runtime.

Java class with native method→ javac -h makes a C header→ You write C++ against that header→ CMake builds libnativeBridge.so→ System.loadLibrary loads it→ Java calls C++ (and C++ can call back)

Everything you need to get, starting from nothing:

PieceWhy you need itWhere it comes from
JDK 17 (not just a JRE)javac compiles Java and writes the JNI header; it also ships jni.h for C++Package manager (section 2.2)
g++ and makeCompile the C++ codePackage manager (section 2.2)
CMakeBuilds the .soPackage manager (section 2.2)
GradleOrchestrates everythingDownloaded automatically by the project's Gradle wrapper. No manual install.

Why CMake instead of Gradle's own C++ plugin? The built-in Gradle C++ plugins are less commonly used and have changed a lot over time. CMake is the industry standard, works the same inside CLion/VS Code, and keeps the C++ side independent of Gradle. Gradle just calls it.

Beginner2. Set up a blank Linux machine

Assume a fresh install: no Java, no compiler, no Gradle, no IDE. Do these steps in order. You need an internet connection and sudo rights.

Master13. Master level: references, threads, exceptions

13.1 The three kinds of references

KindLifetimeUse
LocalUntil the native function returnsDefault for everything JNI gives you. Call DeleteLocalRef inside long loops (the table is limited, around 512 by default).
GlobalUntil you call DeleteGlobalRefAnything you store in a C++ variable between calls (e.g. a jobject callback listener, a jclass).
Weak globalUntil the GC collects itCaches that must not keep objects alive.
Never store a JNIEnv*, a local jobject or a local jclass in a global or static C++ variable and use it later. jmethodID and jfieldID are safe to cache.

13.2 Calling Java from a C++ thread

A background C++ thread has no JNIEnv. You must attach it to the JVM first. Save the JavaVM* in JNI_OnLoad, which the JVM calls once when the library loads:

For this to compile, add public native void startThread(); to NativeBridge.java. Link with threads if needed by adding find_package(Threads REQUIRED) and target_link_libraries(nativeBridge PRIVATE Threads::Threads) to CMake. If the C++ code writes shared data from several threads, protect it with a std::mutex. Note that a detached thread may still be running when main finishes, so in a demo give it time (for example Thread.sleep(500) after the call in Main).

Important Release the global reference (DeleteGlobalRef) when you stop the worker, otherwise the Java object can never be garbage collected.

13.3 Throwing exceptions from C++

Never let a C++ exception escape a JNI function. It will crash the JVM. Wrap risky code in try { ... } catch (const std::exception& e) { throwJava(...); }.

13.4 Registering natives manually (optional)

Instead of the long Java_..._name convention you can register functions in JNI_OnLoad with RegisterNatives. It gives shorter names, a small speed-up, and lets you rename a Java package without touching C++ symbol names. Learn the default convention first; switch later if the project grows.

13.5 Packaging for distribution

  • A plain .jar does not contain your .so. Either ship the .so next to the jar and set -Djava.library.path=..., or bundle it as a resource and extract it to a temp file before System.load(absolutePath).
  • The .so is compiled for one CPU architecture (x86_64 vs aarch64). Build one per target.
  • ./gradlew installDist creates build/install/jniDemo/ with a start script. Pass the library path via applicationDefaultJvmArgs in the application { } block.

13.6 Debugging tips

  • Run with -Xcheck:jni (jvmArgs '-Xcheck:jni' in the run task) to catch many JNI misuse bugs with readable messages.
  • Compile the C++ with -g (-DCMAKE_BUILD_TYPE=Debug) and attach gdb to the java process when you need native stack traces. Install it with your package manager (sudo apt install gdb).
  • Log to stderr from C++ while learning. std::cerr shows in the Run window.

Reference15. Cheat sheet

Blank-machine checklist

  1. Install JDK 17, g++, make, CMake, curl, unzip, git (2.2).
  2. Set JAVA_HOME in ~/.bashrc (2.3).
  3. Run bash checkEnv.sh; every line must say OK (2.4).
  4. Install IntelliJ, or SDKMAN Gradle for terminal-only (2.5 / 2.6).
  5. Create the project, set Gradle JVM to JDK 17 (3).
  6. Add the six project files (4 to 9) and run ./gradlew run (10).

Add a new native function: the 6-step loop

  1. Declare public native ... in Java.
  2. ./gradlew compileJava to regenerate the header.
  3. Copy the new signature from the header into nativeBridge.cpp.
  4. Write the body.
  5. ./gradlew run.
  6. If something fails, jump to section 14.
